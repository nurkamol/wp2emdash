# Blog milestone: posts, taxonomies, bylines, archives, feeds

**Date:** 2026-11-20 · **EmDash:** 1.5.0 (installed source in the pilot project, read-only) · **Astro:** 7.4.12 · **@emdash-cms/gutenberg-to-portable-text:** 1.5.0 · Parity backlog items 1, 4, 5, 6 and 7 (`docs/parity/wp-to-emdash.md`).

## Verified against the installed EmDash 1.5.0

- **Collections / fields** (`seed/types.ts`, `api/schemas/schema.ts`): `SeedCollection` takes `urlPattern`, `supports`, `sortOrder`, `dateField`; fields `string text image portableText blocks boolean` exist (`schema/types.ts FIELD_TYPES`); `searchable` per field. `POST /schema/collections` (`createCollectionBody`: no `dateField`; `hasSeo`) and `POST /schema/collections/{slug}/fields` (needs `validation`, nullable). `validateSeed` accepts the blog seed (run on the fixture's seed: `{"valid":true,"errors":[],"warnings":[]}`).
- **URL patterns** (`schema/url-pattern.ts`): one placeholder per path segment; no date placeholders → the WordPress path is the slug with `/{slug}` (as for pages). Sitemap loc = urlPattern with the encoded slug (the middleware already decodes it).
- **Content REST** (`api/schemas/content.ts`): create/update accept `bylines: [{bylineId}]`, `taxonomies: {name: [termSlug]}`, `publishedAt`; publish accepts `publishedAt` (backdate); `POST /content/{c}/{id}/schedule` `{scheduledAt}`; scheduling on unless `no-scheduling`. List items include `publishedAt`.
- **Permissions vs scopes** (`@emdash-cms/auth` `rbac.ts`, `tokens.ts`; `astro/middleware/auth.ts SCOPE_RULES`): `content:publish_any` is a *role permission* (Editor+), checked against the token owner's role — the kit's `content:write` token (made by an admin) may send `publishedAt`. Taxonomy writes need `taxonomies:manage`, which `content:write` grants implicitly. **Bylines live under `/_emdash/api/admin/bylines`, so the token needs the `admin` scope** (docs/staging-setup.md updated); without it load's `bylines` check fails with that message.
- **Taxonomies** (`api/schemas/taxonomies.ts`, `api/handlers/taxonomies.ts`): `POST /taxonomies` {name `^[a-z][a-z0-9_]*$`, label, labelSingular, hierarchical, collections}; terms list `{terms: [...] }` flat with `parentId`; create `{slug, label, parentId, description}` → `{term}`.
- **Bylines** (`api/schemas/bylines.ts`): slug `^[a-z][a-z0-9-]*$`; `isGuest`, `bio`, `avatarMediaId`; entries store the byline translation group.
- **Query API for templates** (`query.ts`, `loader.ts`, `taxonomies/index.ts`, `bylines/index.ts`): `getEmDashCollection` with `where` (taxonomy name → term slug(s); `byline` → translation group; ranges `gt/lt` on `published_at`), `orderBy`, `limit` + `offset` → `hasMore`; entries carry `data.terms` (grouped by taxonomy), `data.bylines`/`data.byline`, `data.publishedAt` (Date), `data.slug`; boolean fields are INTEGER columns. `getTerm`, `getTaxonomyTerms` (tree + counts), `getBylineBySlug`.
- **Cache tags** (`cache/chrome-tags.ts`, routes): content writes purge `[collection, id]` (so tag `posts` purges every blog page on any post publish); term/definition writes purge `emdash:taxonomy:<name>`; **byline edits purge nothing** — author archives and bylines on cached pages refresh at the route cache's max age.
- **Article meta** (`page/context.ts`, `page/jsonld.ts`): `pageType: "article"` + `articleMeta {publishedTime, modifiedTime, author}` → `article:*` meta and BlogPosting JSON-LD.
- **No RSS anywhere in EmDash** → the starter builds RSS itself.
- **Converter** (`@emdash-cms/gutenberg-to-portable-text` 1.5.0): `gutenbergToPortableText(content, {keyGenerator})`; freeform (classic) parts become one `htmlBlock` unless passed to `htmlToPortableText`; image blocks carry `asset._ref` = the WordPress id as a string (or the URL) and `asset.url`; shortcodes stay text (`core/shortcode` → `htmlBlock`); no wpautop. EmDash's PortableText component renders `image` with `asset._ref` = media id + `asset.url` (the kit writes both).
- **EmDash's own importer** turns password-protected posts into drafts (`astro/routes/api/import/wordpress/execute.ts`); the kit asks for a decision instead.

## End to end (synthetic blog, local EmDash 1.5.0)

The fixture (`test/fixtures/blog/site.json`: Gutenberg + classic posts, sticky, scheduled, draft, private, nested categories, tags, two authors, a posts page) through **transform → load** into a scratch copy of the pilot project (dev server, structure-only setup, so load created the `posts` collection through the schema API): `schema` (collection posts created), `media`, `taxonomies` (6 terms), `bylines` (2), `content` (7 documents), `counts`, `post-dates`, `no-wordpress-leftovers`, `media-integrity`, `id-map`, `render` (2 pages, 2 posts) all passed. Probed on the running site: posts page, category (incl. nested), tag, author archives and their feeds 200; `/journal/page/2/` and unknown terms 404; scheduled and private posts 404; `?p=`, `?cat=`, `?feed=rss2`, date archives 301 to the right address; `/comments/feed/` 410; sitemap index lists pages, posts and `/sitemap/archives.xml`. Both feeds pass `validateRss`. verify's `urls-accounted` judgement of the fixture's 35 old URLs against the running site: all accounted, archives and feeds with real 200s. The seed path (`dev-bypass?content=1` with the blog seed) also renders every blog route. `astro check` (0 errors) and `astro build` pass with a blog config.

## Brochure sites unchanged

Transform + scaffold (no install) of copies of both real sites with the code before and after: `ir/`, `reports/`, `seed/seed.json`, `site.config.json`, `astro.config.mjs`, `wrangler.jsonc` and client docs byte-identical; only kit-owned starter source differs (new blog components and utils, `[...slug].astro`, `Base.astro`, `middleware.ts`, `wp-urls.ts`). A brochure site ships the blog components (their scoped CSS is in the page bundle) but no posts collection, no feed links and `/sitemap/archives.xml` answers 404.

## Not verified yet

- **A real WordPress blog** (Exporter output for posts: the `author` object, `sticky_posts`, `rss_use_excerpt`, `posts_per_rss` and a password field were not seen in a real export; defaults: no author → no byline and the authors row stays undecided; feed = excerpt, 10 items).
- **Remote load with an API token**: the `admin` scope for bylines and `publishedAt` with a token were read in source, not exercised on staging/production.
- **Route cache on workerd**: the cache tags (`posts`, `emdash:taxonomy:*`) are set; purge on publish not measured on a deployed site. Feeds and the archives sitemap are cached like pages.
- **Builder posts on an existing target**: before this milestone they were loaded into `pages`; a site that already loaded builder posts would get them again in `posts` and keep the old page entries (load `counts` reports it). Neither real site had posts.
- Modified dates: EmDash sets `updated_at` at load, so `dateModified` is the load time.
