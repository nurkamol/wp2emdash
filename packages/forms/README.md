# @wp2emdash/forms

Website forms for [EmDash](https://docs.emdashcms.com/) sites on Cloudflare Workers:

- **Form endpoint** — `POST /api/forms/<id>`: honeypot, rate limit, Cloudflare Turnstile (fails closed), validation
  against the form's own fields (nothing else in the request is read), email through Brevo, Resend, Postmark, SendGrid,
  Mailgun or EmDash's own email pipeline (Settings → Email). Works with and without JavaScript. Field values never
  reach logs.
- **Outbox (optional)** — when email is not set up or the provider refuses, the message is kept in Workers KV instead of
  being lost, retried by the Worker's cron, deleted once emailed or after the retention period. A hold switch keeps
  everything and sends nothing (for a provider that accepts mail but does not deliver it).
- **Form messages admin page** — an EmDash native plugin (Block Kit, no React bundle), **admins only**: inbox with
  search, filters, read state and bulk actions; insights (messages per day and per form, from counts only); CSV/JSON
  export through one-time links; import of exported files; activity log; dashboard widget; **Settings**: who form
  messages are emailed to (see below).

Requires EmDash ≥ 1.5 on the Cloudflare adapter (Workers Paid). Generated by and maintained in the
[wp2emdash](../../README.md) kit; the kit's scaffold wires all of this into every migrated site automatically. The
steps below are for any other EmDash project.

## Install

The package is not on npm. Copy `packages/forms` into the project (for example to `packages/forms`) and add it:

```jsonc
// package.json
"dependencies": { "@wp2emdash/forms": "link:./packages/forms" }
```

Or build a tarball from the kit (`pnpm --dir packages/forms pack`) and `pnpm add ./wp2emdash-forms-1.3.0.tgz`.
The package ships TypeScript source; the site's Astro/Vite build compiles it.

## Wire it up

**1. The endpoint** — `src/pages/api/forms/[id].ts`:

```ts
import { createFormEndpoint } from "@wp2emdash/forms/endpoint";
import type { FormDefinition } from "@wp2emdash/forms";
import contact from "../../../forms/contact.json";

const forms = new Map<string, FormDefinition>([[contact.id, contact as FormDefinition]]);
export const prerender = false;
export const POST = createFormEndpoint({ getForm: (id) => (id ? forms.get(id) : undefined) });
```

A form definition (`FormDefinition`): `id`, `title`, `submitLabel`, `successMessage`, `fields` (`name`, `label`,
`type`, `required`, `options`, `autocomplete`, and per type below), optional `notice` and `afterSubmit` (`"hide"` |
`"reset"`). Field types:

| Type | Renders | Posts | Checked |
|---|---|---|---|
| text, email, tel, number, url, date, textarea | one input | the value | length; email/tel format |
| select, radio | a select / a fieldset of radio buttons | the chosen option | one of `options` |
| checkbox | a checkbox | anything = "Yes" | — |
| consent | a checkbox whose label is `labelParts` (text runs; links kept only when http(s) or site-relative — `safeHref`) | anything = accepted | required → must be ticked |
| signature | a signature pad plus "type your full name" (below) | `<name>` PNG data URL and/or `<name>_typed` | PNG or typed name |
| content | `content` blocks (paragraphs, list items, headings, rules; bold, italic, safe links) — not an input | nothing | — |

Rich text (`labelParts`, `content`) is data, never HTML: pages render it as elements (`@wp2emdash/forms/rich` has
`safeHref` and the converters), so nothing in a definition is inserted as markup.

The page renders the form itself and posts `multipart/form-data` to
`/api/forms/<id>` with the fields, `_hp` (an empty honeypot input, visually hidden) and `cf-turnstile-response`
(the Turnstile widget); send `Accept: application/json` for a JSON answer (`{ ok, message, errors? }`), or let the
browser post and come back with `?form=sent|error`.

**2. The admin page** (with the outbox) — `astro.config.mjs`:

```js
import { formsPlugin } from "@wp2emdash/forms";
// …
emdash({ database: d1({ binding: "DB" }), storage: r2({ binding: "MEDIA" }), plugins: [formsPlugin()] }),
```

**3. The cron** (with the outbox) — the Worker entry (`src/worker.ts`, `"main"` in `wrangler.jsonc`):

```ts
import { env } from "cloudflare:workers";
import handler, { createScheduledHandler, PluginBridge } from "@emdash-cms/cloudflare/worker";
import { flushOutbox, type OutboxEnv } from "@wp2emdash/forms/outbox";

export { PluginBridge };
const emdashScheduled = createScheduledHandler();
export default {
	...handler,
	scheduled: async (controller, workerEnv, ctx) => {
		ctx.waitUntil(flushOutbox(env as unknown as OutboxEnv).catch(() => {}));
		return emdashScheduled(controller, workerEnv, ctx);
	},
} satisfies ExportedHandler;
```

with `"triggers": { "crons": ["*/5 * * * *"] }`.

## Configuration (`wrangler.jsonc`, per environment — environments do not inherit)

| Name | Kind | What |
|---|---|---|
| `EMAIL_PROVIDER` | var | `brevo` (default), `resend`, `postmark`, `sendgrid`, `mailgun`, or `emdash` (EmDash's own email pipeline, below) |
| `EMAIL_API_KEY` | secret | The provider's API key (`wrangler secret put EMAIL_API_KEY`); not used with `emdash` |
| `FORM_FROM` | var | Sender, e.g. `Site <noreply@example.com>` — verified in the provider account; not used with `emdash` (the sender is set in Settings → Email) |
| `FORM_TO` | var | Default recipients, comma-separated. An admin can replace them on the Form messages page (Settings tab); that setting wins |
| `MAILGUN_REGION` | var | `eu` for EU Mailgun accounts |
| `TURNSTILE_SITE_KEY` | var | Turnstile widget site key (for the page) |
| `TURNSTILE_SECRET_KEY` | secret | Turnstile secret |
| `FORM_LIMITER` | ratelimits binding | `{ "name": "FORM_LIMITER", "namespace_id": "<unique integer>", "simple": { "limit": 5, "period": 60 } }` |
| `FORM_OUTBOX` | kv_namespaces binding | Turns the outbox on (and with it the admin page's data) |
| `FORM_OUTBOX_DAYS` | var | Retention, 1–90 days (default 30) |
| `FORM_OUTBOX_HOLD` | var | `"1"`: keep every message, send none |

Without working email (no `EMAIL_API_KEY`, or with `emdash` no provider selected in Settings → Email, or no
recipients) and without `FORM_OUTBOX` the endpoint answers 503 ("not available") rather than accept a message it cannot
deliver; with `FORM_OUTBOX` the message is kept and the cron emails it once email works.

**Recipients in the admin.** Plugins → Form messages → **Settings** (admins only, like the rest of the page): up to 10
addresses, one per line, checked before saving. They are stored in the outbox's KV (`cfg:recipients`), so the endpoint
reads them on every message, and the cron and "Email it now" use them too. Order: this setting, else `FORM_TO`. Saving
an empty list goes back to `FORM_TO`. The activity log records who changed them and how many addresses — never the
addresses. Needs `FORM_OUTBOX` (without it, recipients come from `FORM_TO` only).

**EmDash's email pipeline (`EMAIL_PROVIDER=emdash`).** The message goes through whatever the admin set up in EmDash
under Settings → Email — the built-in SMTP provider (needs `EMDASH_ENCRYPTION_KEY` to store its password), the
`EMAIL_SMTP_*` vars, or an email provider plugin — with the sender configured there. EmDash 1.5 does not give an
anonymous request to a site route `locals.emdash.email`, so the endpoint reaches the pipeline through
`withEmDashRuntime()` from `emdash/middleware` (server-only, the same call EmDash's own Worker and AI Search endpoint
use); the cron does the same. The message has one `to` (the first recipient) and the others as `cc`; reply-to is the
visitor's address. When no provider is selected the message is kept in the outbox (or the endpoint answers 503 without
one). EmDash's `email:beforeSend`/`email:afterSend` hook plugins see these messages with source `site-forms`: on a site
with sensitive forms, do not install plugins that hook those events. Turnstile test keys (always pass): site `1x00000000000000000000AA`, secret
`1x0000000000000000000000000000000AA` — for staging and `.dev.vars` only.

## Signatures, consent and the emailed record

**The pad** (`@wp2emdash/forms/signature-pad`, `mountSignaturePads()`, no dependencies; markup in its header and in the
kit starter's `Form.astro`): draw with mouse, finger or pen (pointer events), **Clear signature** button. After each
stroke the drawing is cropped to the strokes, scaled to fit 600×200 on white and written to a hidden input as a PNG
data URL (kept under 150 KB). The canvas is skipped by the keyboard: its label tells keyboard and screen-reader users
to type their full name in the input below it, which is always there (and is the whole field without JavaScript — the
pad stays hidden). A drawing or a typed name satisfies a required signature.

**The endpoint** accepts a drawing only if it is `data:image/png;base64,`, at most 150 KB (checked from the length
before decoding), decodes, starts with the PNG signature bytes and an IHDR chunk, and is at most 600×200; a typed name
is 2–200 characters with a letter and no markup. A refused signature is a 422 on the field. Signatures are never
logged (logs carry the form id, outcome and a reason word).

**The email** is a complete record: form title, submission time (UTC), every answer, consent as
`Accepted: "<the consent text>"`, and — for a form with consent, `content` or a signature — the exact text shown on
the form (terms, consent label with link targets) and its SHA-256, so the record can be checked against the form
later. A drawn signature is sent as an attachment, `signature.png`:

| `EMAIL_PROVIDER` | Signature |
|---|---|
| brevo | attachment (`attachment[{ name, content }]`) |
| resend | attachment (`attachments[{ filename, content }]`) |
| postmark | attachment (`Attachments[{ Name, Content, ContentType }]`) |
| sendgrid | attachment (`attachments[{ content, filename, type, disposition }]`) |
| mailgun | attachment (multipart `attachment` part) |
| emdash | **embedded** in the HTML part as a data-URI image: EmDash 1.5's email message has no attachments. Gmail and some Outlook versions do not show data-URI images — use an API provider for signed forms |

**The outbox** keeps the message with its signature (as base64, in KV) until it is emailed or the retention period
ends, like any message; the cron sends it with the attachment. On **Form messages** a message with a signature says
"signature attached" in the inbox and shows the image on the message page (admins only; only a stored PNG that passes
the same checks is shown). CSV/JSON exports carry the text record, not the image.

## Privacy

- The endpoint reads only the form's own fields and stores nothing unless the outbox is on — then only until the
  message is emailed or the retention period ends.
- With the outbox, one count per day, outcome (emailed / kept) and form is kept for 400 days for the charts: no names,
  addresses or text.
- The admin page is for the **Admin** role only: EmDash enforces `plugins:manage` and its CSRF header before the
  handler runs, and the handler checks the role again. Other roles see "Admins only" (the menu item is visible to them
  in EmDash 1.5; plugin pages have no role filter there).
- Visitor text is shown as plain text. Exports go through a random link that works once, for two minutes, and are
  sent with `Content-Disposition: attachment` under EmDash's sandbox headers; CSV cells that look like formulas are
  neutralised. Imports rebuild the email body from the text (imported HTML is never used).
- The activity log (180 days) and logs record actions and counts, never message content or recipient addresses.
- For sites handling health, legal or financial data, keep forms to contact details only and tell visitors not to send
  sensitive details (`notice` on the form definition).
- **Signatures are personal data.** They are emailed to the recipients and, with the outbox, kept in KV only until
  emailed or for the retention period (`FORM_OUTBOX_DAYS`) — the site is not an archive of signed forms. The business
  should keep the signed emails (a waiver's signed copy) for as long as its own policy and local law require, in its
  own records, and delete them after that. The kit's contact-only policy for sensitive sites withholds radio, consent,
  content and signature fields like any other non-contact field; whether a sensitive site may collect signatures is
  the owner's decision (kit.config `forms.sensitive`).
