Move WordPress to EmDash. Prove nothing was lost.

wp2emdash migrates WordPress sites built with WPBakery, Salient, Gutenberg or the classic editor to EmDash on Cloudflare Workers. It rebuilds pages as editable sections, keeps every URL, image, form and menu animation, and stops at a gate whenever something doesn't match.

Eight phases. Each one ends in a gate.

A phase runs only when every earlier gate has passed or was accepted with a written reason. Gates are data — checks with ids and pass/fail — so the terminal, a CI job, the dashboard and Claude Code all read the same result.

  1. ready

    init

    Workspace, config, access & backup checklist the owner signs off.

  2. ready

    audit

    Crawl, screenshots, design tokens, menu motion, forms & integrations — public site only.

  3. ready

    extract

    Raw content, meta, SEO, menus, form definitions and media via the EmDash Exporter. Read-only.

  4. ready

    transform

    Builder layouts → a typed section format, with coverage and text-conservation gates.

  5. ready

    scaffold

    EmDash project: section library, tokens, header & burger menu from the recipe, local preview.

  6. ready

    load

    Content and media into local, staging or production through the EmDash API; an id-map makes reruns idempotent.

  7. ready

    verify

    Old vs new, URL by URL: text, SEO, links, forms, a11y, performance, and a visual diff per section on phone, tablet and desktop.

  8. preflight ready

    cutover

    Read-only preflight and runbook; then, with the owner's approval, a Worker route in front of WordPress, smoke tests and one-step rollback.

Built for migrations that have to be right

The hard parts of leaving WordPress aren't the posts. They're page builders, theme options, forms, booking widgets, menus that animate, and URLs Google already knows. wp2emdash treats each of those as a check.

Real builder adapters

A shortcode parser and block parser, not regex. WPBakery rows, Salient elements and Gutenberg blocks become hero, FAQ, pricing, team and 16 more section types.

Text conservation

Every word on the live page is compared with the migrated content — against WordPress's own HTML, not the adapter's opinion of it.

Motion parity

The burger menu's animation is measured with the Web Animations API — durations, easing, stagger — and reproduced as CSS variables, with accessibility fixed rather than copied.

Forms & integrations

Every form and widget found, with fields, recipients and a decision: keep, rebuild natively, replace or drop. Booking embeds stay on an allowlist.

Safe by default

Read-only towards WordPress. Never reads form submissions. Secrets stay in a local .env. Production changes need the owner's explicit approval.

Editable afterwards

Pages arrive as EmDash sections with plain fields — the client edits text, images, buttons and menus in the admin; the design stays consistent.

Visual parity, measured

Every section is compared with the live site at phone, tablet and desktop widths. Spacing and type come from the builder's own settings, measured on the live theme — not eyeballed.

Forms that deliver

A native endpoint with Turnstile, rate limiting and validation; email through Brevo, Resend, Postmark, SendGrid or Mailgun; an optional outbox in Workers KV that holds messages until email works.

SEO and old URLs kept

Titles, descriptions, structured data, sharing images and the sitemap carry over; old upload and sitemap addresses redirect; analytics ids move without copying scripts.

Tested on a real site first

The pilot is a ten-page clinic site on Salient + WPBakery with Rank Math, Fluent Forms, Popup Maker and two booking systems. It runs in production on Cloudflare, waiting for the owner's go-live.

What it migrates

Builders are adapters. Anything an adapter can't map shows up in the coverage report and blocks the gate — nothing is dropped silently.

Get started

Requires Node.js 24+ and pnpm. Generated sites deploy to Cloudflare Workers (Workers Paid plan) on the latest Astro that EmDash supports.

# install
git clone https://github.com/OWNER/wp2emdash
cd wp2emdash && pnpm install
pnpm wp2emdash doctor

# create a site workspace (or just run `pnpm wp2emdash` for the wizard)
pnpm wp2emdash init --slug acme --name "Acme Clinic" --source https://www.example.com

# run the phases in order; each stops at its gate
pnpm wp2emdash run acme audit
pnpm wp2emdash run acme extract
pnpm wp2emdash run acme transform
pnpm wp2emdash run acme scaffold

# preview the migrated site locally
cd sites/acme/project && pnpm dev

# load into staging and compare it with the live site
WP2EMDASH_LOAD_TARGET=staging pnpm wp2emdash run acme load
WP2EMDASH_TARGET=staging pnpm wp2emdash run acme verify

# check everything the switch-over needs (read-only)
pnpm wp2emdash run acme cutover
